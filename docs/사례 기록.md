## 클로드가 잘못 추론하거나 답한 사례(7.1절 6항 후보)

### 1. 어려운 해결 기능 개수를 7개로 적음 (2026-10-28)

- 무엇: PRD 초안을 쓸 때 공고 3장 표의 기능은 8개(다른 사람의 변경 보기, 필수 포함 역할, 같은 팀 대기 지원, 마지막 자리 동시 입장, AI 응답 지연, 3차 모델까지 실패, AI 대기 화면, DB 일시정지)인데 "7개"라고 적음. 채팅 설명에서도 8가지를 나열하고 "7개"라고 함.
- 알아챈 방법: 사용자가 "공고 PDF와 어려움 해결 부분이 일치하는지 확인해 줘"라고 요청해, 3장 표를 한 줄씩 대조하다 발견함.
- 고친 곳: PRD 1.4절과 5장 제목을 8개로 고친 뒤 처음 커밋함(a8a391b).
- 근거: 대화 화면 캡처(사용자가 남길 것).

### 2. 검토 에이전트가 명단 CSV의 역할 열을 약자로 추론함 (2026-10-28)

- 무엇: PRD를 검토한 서브에이전트가 `학생3(PL;TT)` 같은 이름을 보고, CSV 역할 열에 PL, TT 같은 약자가 들어간다고 추론하고 약자 대응표가 필요하다고 질문함.
- 알아챈 방법: 공고 2.6절의 CSV 예시와 받은 `어려움.csv`를 대조해, 역할 열은 `기획자` 같은 한국어 이름이고 괄호 속 약자는 이름 열의 일부임을 확인함.
- 고친 곳: PRD 1.3절에 이 사실을 밝혀 둠(a8a391b).

### 3. Supabase 지역을 Seoul로 안내함 (2026-10-28)

- 무엇: Supabase 프로젝트를 만들 때 Region을 Northeast Asia (Seoul)로 고르라고 안내함. 그런데 앱은 Streamlit Community Cloud(미국)에서 돌기 때문에, DB가 서울에 있으면 질의마다 태평양을 왕복해 화면이 느려짐.
- 알아챈 방법: Task 4에서 DB 연결 코드를 설계하며 질의 한 번의 왕복 시간을 따져 보다가, Streamlit 문서(Status and limitations of Community Cloud)에서 "모든 앱은 미국에서 호스팅되고 바꿀 수 없음"을 확인함.
- 고친 곳: 사용자에게 East US (North Virginia)로 다시 안내함. 화면 한 번에 DB 질의가 한 번만 가도록 `service.load_snapshot`을 한 질의로 설계함.

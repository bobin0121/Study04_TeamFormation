# 팀 편성 웹 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공고의 팀 편성 웹 앱을 어려운 해결 8개로 만들어 Streamlit Community Cloud에 배포하고, 연습 시나리오 3개를 배포한 앱에서 통과시킨다.

**Architecture:** 판정은 모두 `rules.py`의 순수 함수가 한다. `service.py`가 DB 트랜잭션 안에서 상태를 읽고 `rules.py`에 판정을 맡긴 뒤 결과를 쓴다. `streamlit_app.py`는 `service.py`만 부르고, 결과를 `Outcome`(첫 단어 + 이유)으로 받아 `result`에 보여 준다.

**Tech Stack:** Python 3.11, Streamlit 1.66.1, psycopg2-binary 2.9.13, bcrypt 5.0.0, requests, python-dotenv, pytest, Playwright(검증 전용)

**Spec:** `docs/PRD.md`(근거는 「중간 과제 공고」). 실행하는 사람은 PRD를 함께 읽는다.

## Global Constraints

- 테이블 이름은 모두 `tf_`로 시작한다.
- 역할 6개(이 글자 그대로): `기획자`, `웹 프로그래머`, `프론트엔드 디자이너`, `테스터`, `보고서 작성자`, `발표자`
- `result` 안내는 `승인: `, `대기: `, `거절: `, `막힘: ` 가운데 하나로 시작한다(첫 단어 + 쌍점 + 공백).
- 화면 key는 PRD 7.2절 표와 한 글자도 다르면 안 된다. key에는 영문, 숫자, 밑줄만 쓴다.
- 키 3개(`OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`)의 값을 코드에 적거나, 출력하거나, 로그나 예외 안내에 넣지 않는다. 확인은 "있음, 없음"만 한다.
- DB 연결 오류는 잡아서 `DB에 연결할 수 없음.`처럼 이유 없는 문구만 보여 준다. psycopg2의 `invalid dsn` 오류는 연결 문자열(비밀번호 포함)을 메시지에 담기 때문이다. 같은 이유로 `.streamlit/config.toml`에 `[client] showErrorDetails = false`를 두어, 예상하지 못한 예외의 내용도 화면에 나오지 않게 한다(공고 6.3절 8번).
- 테스트 코드에도 비밀번호처럼 보이는 고정 문자열을 두지 않는다. 테스트용 관리자 비밀번호는 `secrets.token_hex(8)`로 그때그때 만든다(공고 6.3절 7번).
- 화면에 시각을 보여 줄 때는 `Asia/Seoul`로 바꿔 보여 준다(배포 서버는 UTC). `zoneinfo`를 쓰면 `tzdata`를 의존성에 넣는다.
- README용 화면 캡처는 앱 영역만 잘라, 브라우저 프로필이나 계정 이름 같은 실제 개인정보가 나오지 않게 한다(공고 6.3절 9번).
- `DATABASE_URL`은 Supabase의 **Session pooler** 주소(포트 5432)를 쓴다. Streamlit Cloud와 GitHub Actions는 IPv4만 되고, 시험용 스키마의 `SET search_path`가 연결 동안 유지되어야 하기 때문이다.
- 학생 비밀번호는 `1234`, 관리자 학번은 `admin`, 팀 이름은 `팀1`, `팀2`, …
- 모델마다 전체 대기 시간은 120초. 무료 모델 자동 라우터 `openrouter/free`는 쓰지 않는다.
- 자동 갱신 간격은 2초(`st.fragment(run_every=2)`). 처음 계획은 3초였으나 E2E 검증에서 마감 직후 단추가 늦게 바뀌는 문제를 보고 줄임.
- 새 파일 맨 위에 `생성: YYYY-MM-DD HH:MM KST` 주석을 단다(`date "+%Y-%m-%d %H:%M"`로 확인).
- 한국어 문구는 사용자 CLAUDE.md 6절을 따른다(가운뎃점 대신 쉼표, 완결된 문장 안내는 마침표로 끝냄, 보조용언 띄어 씀). 단, `result` 안내는 PRD에 적힌 문구 그대로 쓴다.
- 연습 시나리오의 이름이나 순서를 보고 결과를 정하는 코드는 쓰지 않는다(공고 6.3절 19번). 시나리오는 테스트에만 쓴다.
- 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 단다.

# tests/test_rules.py
T = lambda no, main, *subs: Student(no, f"s{no}", main, tuple(subs))

def test_filled_required_counts_distinct_people():
    assert filled_required_count([T("1", PL, WP)]) == 1          # 공고 예: 혼자 둘 다 해도 1
    assert filled_required_count([T("1", PL), T("2", WP)]) == 2
    assert filled_required_count([T("1", "테스터", PL), T("2", "프론트엔드 디자이너", WP)]) == 2
    assert filled_required_count([T("1", "테스터"), T("2", "발표자")]) == 0

def test_required_slot_examples_from_notice():
    # 테스터, 발표자 팀에 보고서 작성자: 남는 자리 1 < 2 -> 막음
    assert not required_slot_ok([T("1", "테스터"), T("2", "발표자"), T("3", "보고서 작성자")])
    # 같은 팀에 기획자: 남는 자리 1, 채우지 못한 역할 1 -> 통과(PRD 4.1 해석)
    assert required_slot_ok([T("1", "테스터"), T("2", "발표자"), T("3", PL)])
    # 남는 자리 2, 채우지 못한 역할 2 -> 통과(부록 3의 10단계)
    assert required_slot_ok([T("1", "테스터", "발표자"), T("2", "발표자", "프론트엔드 디자이너")])

def test_apply_block_order():
    a = T("9", PL)
    full = [T(str(i), r) for i, r in enumerate(["테스터", "발표자", WP, "보고서 작성자"])]
    assert apply_block_reason(closed=True, has_team=True, has_pending=True, members=full, applicant=a) == R_CLOSED
    assert apply_block_reason(closed=False, has_team=True, has_pending=True, members=full, applicant=a) == R_HAS_TEAM
    assert apply_block_reason(closed=False, has_team=False, has_pending=True, members=full, applicant=a) == R_PENDING
    assert apply_block_reason(closed=False, has_team=False, has_pending=False, members=full, applicant=a) == R_FULL
    assert apply_block_reason(closed=False, has_team=False, has_pending=False, members=[T("1", PL)], applicant=a) == R_SAME_MAIN
    assert apply_block_reason(closed=False, has_team=False, has_pending=False,
                              members=[T("1", "테스터"), T("2", "발표자")], applicant=T("3", "보고서 작성자")) == R_REQUIRED
    assert apply_block_reason(closed=False, has_team=False, has_pending=False, members=[], applicant=a) is None

def test_recheck_same_main_role():
    members = [T("2", PL, "발표자"), T("8", "프론트엔드 디자이너", "테스터"), T("5", WP, "프론트엔드 디자이너")]
    assert recheck_reason(members, T("6", WP, "보고서 작성자")) == "승인 직전 검사에서 같은 주 역할의 팀원이 있음"
    assert recheck_reason(members[:2], T("5", WP)) is None

def test_vote_state():
    assert vote_state({"1", "4"}, {"1": "찬성"}) == "대기"
    assert vote_state({"1", "4"}, {"1": "찬성", "4": "찬성"}) == "전원찬성"
    assert vote_state({"1", "4"}, {"1": "찬성", "4": "거부"}) == "거절"

```python
def find_assignment(teams, unassigned):
    order = sorted(unassigned, key=lambda s: len(_fits(s, teams)))   # 갈 수 있는 팀이 적은 학생부터
    cur = {t: list(m) for t, m in teams.items()}
    plan = {}
    def need():  # 2명이 안 된 팀을 채우는 데 더 필요한 사람 수
        return sum(max(0, 2 - len(m)) for m in cur.values())
    def go(i):
        if need() > len(order) - i:
            return False
        if i == len(order):
            return all(not team_errors(t, m) for t, m in cur.items())
        s = order[i]
        tried_empty = False
        for t in sorted(cur):
            m = cur[t]
            if len(m) >= 4 or any(x.main_role == s.main_role for x in m):
                continue
            if not m:
                if tried_empty:
                    continue          # 빈 팀끼리는 바꿔도 같은 배정
                tried_empty = True
            m.append(s); plan[s.student_no] = t
            if not (len(m) == 4 and filled_required_count(m) < 2) and go(i + 1):
                return True
            m.pop(); del plan[s.student_no]
        return False
    return dict(plan) if go(0) else None
```

`call_with_deadline`은 `with ThreadPoolExecutor()`를 쓰지 않는다. `with`를 빠져나갈 때 스레드가 끝나기를 기다려서 120초 제한이 깨지기 때문이다.

```python
def call_with_deadline(fn, deadline_sec, on_tick):
    box, done = {}, threading.Event()
    def work():
        try: box["v"] = fn()
        except BaseException as e: box["e"] = e
        finally: done.set()
    threading.Thread(target=work, daemon=True).start()
    start = time.monotonic()
    while not done.wait(timeout=min(1.0, max(0.0, deadline_sec - (time.monotonic() - start)))):
        elapsed = time.monotonic() - start
        if elapsed >= deadline_sec:
            raise AIError(f"{int(deadline_sec)}초 안에 응답 없음")
        on_tick(elapsed)
    if "e" in box: raise box["e"]
    return box["v"]
```

`run_assignment`의 순서(PRD 6.1절 2~5번):
1. `find_assignment`가 `None`이면 AI를 부르지 않고 `AssignResult(None, "", [], infeasibility_reasons(...))`
2. 모델 i(1~3)마다 `on_progress(f"{i}차 모델({model})의 응답을 기다리는 중 ({경과}초 / {deadline}초)")`를 1초마다 부른다 → 응답을 해석하고 `validate_plan`을 거친다 → 실패면 `failures`에 `f"{i}차 모델({model}) 실패: {이유}"`를 더하고 `log(...)` → 성공이면 `AssignResult(plan, f"{i}차 모델 {model}", failures, [])`
3. 셋 다 실패면 `AssignResult(1번의 배정, "앱 자체 배정", failures, [])`
